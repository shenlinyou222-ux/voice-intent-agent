### 2. 唯一意图开关（一份 json）
- 文件：`voice_agent/intent_config.json` → **第一个 key** `intent_registry`
- 每条固定 6 字段：`intent / says / pinyin / desc / enabled / tag`（45 条：system 16、日常 7、游戏 1、运维 21）
- `enabled`：true=参与 ｜ false=不参与（任何路径都不执行）；**参与 = enabled 且（tag==当前域 或 tag==system）**
- `pinyin`：说法的拼音标注，加载时自动核对，不一致打 WARN（当前 0 条不一致）
- 打开类三件套（launch_app/open_url/open_file）`says` = `打开X/启动X/…`，匹配时按 json 自己的 apps/urls/files 逐条展开（arg=名字）
- 三个 profile 的 `behavior.intent_registry_file` 都指向这一份；旧的 `table_*.json` 退场
- 加载器：`opencode_fastpath/intents.py`（mtime 热加载 + 拼音校验 + ACTIONS 门槛 + 闭集代理）

### 3. 领域（默认「日常」）
- 说：`切换到日常/游戏/运维`（或 `日常模式` 等）→ `opencode_fastpath/domains.py` → `intents.set_domain()`
- 落盘：`opencode_fastpath/domain_state.json`（按 profile 记；重启保持）
- 优先级：运行期选择 > profile 的 `behavior.intent_domain` > 兜底「日常」
- 各域实测：日常（打开B站 ✅ / 补农 miss）｜游戏（补农 ✅ / 查磁盘 miss）｜运维（查磁盘 ✅ / 补农 miss）；打开类在**任何域**都开（system）

### 4. 路由（两条路）
| 路 | 何时跑 | 做什么 |
|---|---|---|
| A 路 | 有分段/流式时，段转写完成后 | ① 先试**模式匹配**（带变量的命令）② 再查唯一开关的掩码表（**全子串**、整条说法 kind=1）→ 命中即执行并记账 |
| B 路兜底 | 主路径判成 unknown 时（`final_intent == "unknown"` 之前） | 同样的模式匹配 + 掩码表（**全子串**），命中即执行，**不再掉成听写** |

- **★ 2026-10-19 核心算法变更（用户拍板）：掩码匹配从「只认句尾子串（tail_only）」改为「全子串扫描」**
  - 目的：前后缀不影响命中 ——「那个帮我打开炉石传说吧」「嗯……我现在想打开炉石传说，可以吗」都能命中
  - 实现：`fastpath.route_prefix` 对每个起点 `s` 向右增量 OR 掩码，长度 ≥ `min_prefix` 就查一次表；O(n²) 位运算 + O(n²) 哈希查表（38 字长句实测 5.2ms）
  - 排序：整条说法 `kind=1` 优先于前缀行 `kind=2`；同类里**跨度最长**优先；长度相同取靠前
  - 新增护栏：**两字说法（关闭/关掉/退出/结束/停掉）不乱触发** —— 只在句首、或后面只剩语气词（吧/啊/呀/了…）时才允许；「我觉得应该关闭它」不会触发，「把浏览器关掉吧」会触发
  - 兼容：`tail_only` 参数保留但不再限制范围，只参与同分排序
  - 回归：`selfcheck` 43/43（含"子串匹配(前后缀不影响)"、"两字说法只认整句"）

- 假命中护栏：整句路由只认 **kind=1（整条说法）**；只命中"前缀行"（kind=2，给逐字早火用）一律不执行并打日志
- 命中但动作失败：消费本句 + 打 WARN（不再掉听写）；"未知意图"才交回主路径
- 参数化（带数字）命令：`intents.PATTERNS`（regex）+ 中文数字 `cn2int`（五→5、十二→12、一百零五→105）

### 5. VAD / 灵敏度（三个可校准参数）
| 参数 | 当前值 | 说明 |
|---|---|---|
| 起判门 | `prob 0.30` + `hits 1` + `平滑 2` | 原 0.4/2/3 会漏掉短口令/起音（已实测） |
| AGC | `vad_max_gain 80` / `vad_target_rms 0.05` | 原 60/0.03，顶格也拉不够 |
| 停止窗 | `19 帧 ≈ 608ms` | 语音校准会写；**下限 512ms**，测不到句内停顿时不下调 |
| 预滚 | `砍 0ms`（640→640）+ `起点前 250ms` | 现场校准会按段首能量比调整 |
| ASR 前增益 | `asr_gain_cap 200` | 小声时语音校准会抬（复核空文本则再翻倍） |
| 自适应该 | 拼接=切碎→停止窗+1 帧；持续有声未出段→prob−0.03（≥0.25）| 回收到`配置值`为止（不再硬编码 0.40） |
| 档案 | `opencode_fastpath/vad_profiles.json`（`default`：prob 0.3 / hits 1 / misses 19）| 优先于配置 |

### 6. 语音校准与诊断（任何域）

### 7. 听写（非命令的话）
- `enable_dictation=true`；`dictation_punct_to_space` 标点→空格；终端里 **auto 不自动听写**（要显式「开始输入」）、不加尾随空格、跳过回读验证
- 「关闭输入」后：不匹配意图的话**不打进输入框**，并明说 `🔇 听写已关闭…忽略、未打进输入框`
- 听写验证：30ms 轮询确认（原固定 sleep 150ms）

## 三、可能的问题（按优先级）

### A. 真问题（建议改）
1. **`fav_open / fav_show / fav_sync` 不在清单里** → 不可见、无法用 enabled 关掉（pattern 能命中，但 `enabled()` 查不到就默认放行）。
   → 修：往 `intent_registry` 加 3 条 system 条目（says + pinyin + desc 写清「第N条」走模式匹配）。
2. **aoe4 profile 还是 `log_level=debug`**（上一轮为排查留的）→ 日志膨胀：电平 5s/行、麦克风小结 30s/行、每段全部细节。
   → 修：改回 `info`（要看细节临时 `VOICE_AGENT_LOG=debug` 启动）。
3. **按需取第 N 条那次验被中断，还没跑通过一回**（412 之后我加了 buvid3 + 退避，但没拿到成功结果）。
   → 要么补验一次（1 次请求，风险低），要么先放弃收藏夹这条线。
4. **含 `X` 的字面说法没有护栏**：加载器优先用 apps/urls/files 展开；万一那份闭集被清空，「打开X」会按字面装进表，裸词「打开」就会命中 `launch_app(arg=None)`。
   → 修：安装时跳过含 `X` 的字面说法（1 行）。
5. **生成物残留**：`opencode_fastpath/table_registry.json`（旧版 fp 落盘，已不再写）、`语音命令列表.md`（旧版命令列表）、`fav_cache/明日方舟.json|.md`（412 时的 0 条残料）。
   → 修：删掉即可（不影响运行）。
6. **键鼠自动化是硬编码坐标**（我按截图量的 1920×1080），脆弱且可能点错东西。
   → 若要做成意图：必须"截图 → 看图 → 算坐标 → 点 → 再截图复核"，并且只在前台类=`Chrome_WidgetWin_1` 且标题含 bilibili 时才点。
7. **麦克风监控那两行不在 INFO 白名单** → `log_level=info` 时看不到（与"能看到监控"的预期不符）。
   → 要么白名单加 `🎧 `，要么明确：监控只在 debug 看。

### B. 设计取舍（要你拍板）
8. **打开类三件套 tag=system** → 游戏域里说「打开B站」也会开浏览器。不想这样就把那 3 条 tag 改回 `日常`（一行）。
9. **听写**：终端要显式「开始输入」，但浏览器/聊天框仍是 auto 自动打字。想全局别自动打字 → 说「关闭输入」。
10. **模式匹配的时机**：只在 A 路最前 + B 路 unknown 兜底。若规则/模型把「打开第5条」判成别的意图（非 unknown），就走不到模式匹配。
11. **`file_search / exact_search / site_search / close_app` 仍是「日常」标签**（游戏/运维域不参与）→ 要不要也改 system。
12. **DSH 两条**（`dsh_run/dsh_new`）= `enabled:false` + 空说法（唯一不符合"统一格式都有说法"的两条）→ 删掉 or 补说法恢复。
13. **说话人档案只有 `default`** → 多人/多麦共享同一组 VAD 参数（既有设计）。
14. **`patch --status` 只校验 marker/补丁数量**，不校验每个补丁内容是否被手改；靠备份回滚。
