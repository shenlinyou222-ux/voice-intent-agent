语义（严格加法）：
1. 先跑 `voice_agent` 原逻辑（规则/embed/model）——**已知命令行为不变**；
2. 仅当原逻辑给 `unknown` 且快路径命中：
   - `shadow`：只写 `a_path`/`rescue` 日志，结果仍是 unknown；
   - `live`：仅接管 `additive=True` 且非破坏性的条目 → **0 模型**；
3. A 路（段级）在 `_a_worker` 里就执行，写入 `_a_executed`，B 路整段兜底会自动去重；
   **live 模式本身就是执行开关**（`run_opencode_live.cmd` / `OPENCODE_FASTPATH=live`），
   不依赖 `intent_config.json` 里的 `stream_exec`（他们的默认是 false）；
4. 破坏性意图即使在 live 也回退原路径，除非显式 `OPENCODE_FASTPATH_DESTRUCTIVE=1`。

## 语义细节

- 折叠组对齐 `phon_match.py` 的保守集合（zh/z ch/c sh/s n/l r/l f/h j/q/x g/k；an/ang en/eng in/ing ian/iang uan/uang o/uo ai/ei），**刻意不折 t/d、b/p**。
- 未见过的音节 → `mask=None` → `MISS`（不猜）；表外字用散列字段，不静默丢弃。
- 前缀行只注册 **≥3 字**，且仅作未来流式早火用；当前钩子只消费全串行键。
- 基表 42 条目 / 738 触发器 / 408 全串行 + 1176 前缀行 → **160KB**（实测）。
- 破坏性放行：`set OPENCODE_FASTPATH_DESTRUCTIVE=1`（仅在你明确要 fastpath 接管时）。

## 边界（诚实声明）

- A 路是**段级**（他们当前设计：VAD 段整段转写后 `handle()`）——快路径已在 `_a_worker` 段转写后立即介入；
